# V1 交互与数据行为规范

更新：2026-10-21。配套 [V1 需求](LIFE_CANVAS_V1_REQUIREMENTS.md)，用于把原型转换为正式产品。本文的“实现默认”是本轮为消除开发歧义作出的决定，不代表用户逐项指定；修改默认时同步需求、接口和验收。

## 1. 已确定的页面与操作

| 区域 | 手机端 | PC Web |
| --- | --- | --- |
| 一级导航 | 饮食、日记、AI、我的 | 饮食记录、日记、AI 对话、设置 |
| 饮食 | 首页直接显示当天三餐；就近记录、编辑、补用量 | 三餐为主体；右侧年月日历与当天日记入口 |
| 日记列表 | 搜索、日期筛选、新建；隐私只用锁图标表示 | 编辑区左边独立显示所有日记，可搜索、筛选、新建 |
| 日记编辑 | 全屏；标题和正文聚焦无输入边框；底部格式工具栏 | 中间编辑；正文常规左边距 32px；工具栏紧接标题；专注模式收起导航和两侧栏 |
| 日记设置 | 右上入口展开下拉，包含心情、标签、日期、AI 使用限制、修订与删除 | 右侧上方常驻日历、下方常驻设置；三栏独立滚动 |
| 日记保存 | 自动保存，无手动保存按钮，无独立预览入口 | 同左；书写 / Markdown 是两种编辑方式 |
| AI 空白会话 | 小尺寸图标、简短引导与弱化说明；示例靠近输入区 | 同样突出对话，左侧独立会话列表 |
| AI 已有会话 | 隐藏欢迎内容；确认具体修改后执行 | 同左 |
| 通用表单 | 返回左上、关闭右上；需要显式保存的表单在底部右侧保存 | 保持相同语义；餐次用右侧抽屉编辑 |

标签逐个添加，回车或加号提交，标签可独立移除；中文组合输入中的回车不能误提交。日历支持切换年月、跨年与闰年，翻月不改变已选日期。交互不依赖颜色单独表达状态，支持键盘焦点、读屏标签与减少动态效果。

## 2. 本轮采用的实现默认

| ID | 默认规则 | 理由与边界 |
| --- | --- | --- |
| D01 | 一天允许多篇日记；日期不是日记唯一键 | 原型有新建独立篇目；避免补记覆盖已有日记 |
| D02 | 正文以 Markdown 为唯一可编辑持久化源，纯文本/HTML 是派生结果 | 手机、PC、导出与 AI 使用同一正文，避免两个副本互相覆盖 |
| D03 | 每次有实际变化的云端提交生成一个不可变修订；首个保存为版本 1 | 修订与并发版本对应；无变化的重试不增加版本 |
| D04 | 停止输入 650ms 后自动保存；同篇日记最多一个请求在途 | 延续原型手感，避免请求乱序导致丢字 |
| D05 | 新日记默认不提供给 AI，心情未选为 null | 隐私默认收紧；“选填”不应被自动写成平静 |
| D06 | 删除、标记未吃、餐次保存及 AI 修改成功后提供 8 秒撤销 | 延续原型；以服务端时间及版本校验为准 |
| D07 | 新建/切换 AI 会话只改变当前视图；取消旧任务必须明确点击停止 | 云端任务与页面生命周期分开，避免误取消跨设备审批 |
| D08 | 标签最多 10 个，每个最多 16 个 Unicode 字符；标题最多 200 个字符；正文最多 1 MiB UTF-8 | 作为首版校验边界；客户端和服务端统一，不静默截断 |
| D09 | Markdown 导入文件最多 1 MiB，创建新日记；修订首版只读查看 | 与当前 PC 原型一致；不增加历史版本一键恢复功能 |
| D10 | 已知食物用量最多 14 位整数、6 位小数，严格十进制校验 | 对应 numeric(20,6)，超限明确报错，不四舍五入保存 |

## 3. 日记编辑、日期与筛选

- 新建先生成客户端请求标识并展示空编辑器；标题、正文及已完成的附件均为空时，不创建云端日记。只有心情/标签变化仍视为空篇。已有日记清空文字属于正常编辑，不等于删除。
- 点击左侧列表打开原篇目，日历定位其日期。默认列表按 `journal_date DESC, created_at DESC, id DESC` 排序；编辑正文不改变原记录时间。
- PC 右侧日历的圆点表示该日存在日记；选日期打开当天创建时间最新的一篇，并清除列表搜索/日期筛选以显示全部日记。同日其余篇目仍可从左侧打开。
- 空日期显示“这一天还没有日记”和补记入口；补记采用该日期。列表顶部“写日记”默认今天，二者不混用。
- 右侧日历“回到今天”只将视图翻回今天所在月份；选具体日期才切换内容。日记日期浏览不得改变饮食页选中日期或现有日记归属日。
- 修改归属日必须通过日记设置；保存 `journal_date` 与记录时区，修改个人时区不移动历史日记。日期范围沿用原型 1900–2100 年。
- 搜索标题、正文与标签；搜索和显式日期筛选可组合，清除后恢复全部记录。列表分页必须保持日期、时间和 ID 的稳定排序。
- 已打开草稿有未保存修改时，列表切换、导航、筛选导致的重绘都先执行第 4 节的离开处理。

## 4. 自动保存与多端冲突

| 状态/事件 | 正式产品行为 |
| --- | --- |
| 输入/格式/标签等变化 | 立即更新当前草稿；显示“未保存”，650ms 无新输入后提交 |
| 中文输入组合 | composition 结束后再计时；组合过程中不保存半成品或重新挂载编辑器 |
| 请求在途又继续输入 | 保留较新的草稿；旧响应仅确认其对应快照，用返回的新版本提交后续快照，不能覆盖当前输入 |
| 云端提交成功 | 只有全部待保存变化均被服务器确认后显示“已保存”；返回 version 与 updated_at |
| 无实际变化 | 不产生修订；同内容幂等重试返回已有结果 |
| 请求失败/断网 | 草稿留在当前页面，显示“未保存/保存失败”，可重试；不假装已同步 |
| 页面内返回/切换日记 | 立即提交并等待完成；失败则留在原处，提供重试、复制内容、明确放弃的选择 |
| 应用进入后台/关闭标签页 | 尽力提交，仍存活的进程保留草稿；不能宣称退出或系统杀进程后必然恢复 |
| 拉到其他设备的新版本 | 本地干净时更新；有草稿或在途请求时不覆盖编辑区 |
| 收到 409 | 暂停自动保存，保留当前草稿，显示云端最新版本与本地草稿以供核对 |
| 冲突解决 | 可复制草稿、采用云端并确认放弃草稿，或保留草稿继续核对；再次提交必须绑定展示过的最新 version，再冲突继续提示 |

不自动覆盖云端，不做未经用户查看的自动合并。普通活跃业务页面每 15 秒检查变化，正常网络下其他活跃设备在 30 秒内可见修改；进入页面、前台恢复、网络恢复和手动刷新立即重取。编辑期间刷新只更新服务端缓存及冲突提示。

撤销输入/格式操作是编辑器本地历史；对已成功保存的文字执行撤销后，作为新修改自动保存，不能回退服务器版本号。日记修订按版本分页，只读查看，包含标题、正文及心情/标签/隐私/日期/附件引用快照；新建及实际更改才产生快照。V1 不自动淘汰修订，删除日记时一并删除。

## 5. Markdown 与图片的跨端规则

### 5.1 支持范围

共同正文格式为标题、段落、加粗、斜体、有序/无序列表、任务列表、引用、行内代码、代码块、表格、链接、分隔线和图片引用。PC 提供格式化书写与源码编辑；切换模式不产生额外的只读预览页。

手机保留常用格式工具并能显示上述内容。对编辑器不能保真编辑的复杂块，首版采用只读块保留，可编辑其前后文字，不允许把表格、代码、图片或链接静默转换为纯文本。正式编辑器选型须通过该场景再定，不能直接把原型 contenteditable 当成生产实现。

未编辑正文时，源码往返应保持原文；有结构编辑时允许等价 Markdown 规范化，但语义、顺序和所有受支持块不能丢失。语法高亮主题、公式、双向链接与第三方专用语法不属于首版；不支持的源码必须保留并提示，不能静默清除。

正文不持久化第二份可编辑 HTML；服务端派生纯文本用于搜索，HTML 显示时清理。原始 HTML、脚本和不安全链接不得执行。外链图片不自动加载或由服务器代抓，保留引用并显示占位，避免打开日记即访问第三方。

### 5.2 图片入口与保存

- 手机日记底部格式工具栏提供添加图片，PC 标题下工具栏提供同语义入口；插入光标位置。餐次照片仍在备注与照片区域。
- 接受 JPEG/PNG/WebP，单张最大 10 MiB。手机将 HEIC 转换到支持格式、修正方向、压缩，并去除位置信息；服务端复核真实类型、大小和归属，不能只信扩展名。
- 上传进度就近显示，可取消/重试。成功登记为 ready 的附件才能进入已保存正文；图片仍上传时正文文字可保存，但页面同时显示“图片上传中”，不能宣称整篇已完成保存。
- 使用内部引用 `attachment:<uuid>`，不将签名下载 URL 写入 Markdown。引用必须属于当前账号、当前日记，服务端在保存事务中校验。
- 空白篇第一次插图采用暂存上传；上传完成后以正文与附件关联原子创建日记。失败或取消不生成只有空壳的日记，未引用暂存文件由任务清理。
- 从当前正文移除图片后，历史修订仍可引用原图，因此不能立即销毁对象；只在当前正文和全部有效修订均不再引用或日记删除后清理。

### 5.3 文件导入导出

PC `.md` / `.markdown` 导入创建新日记，第一行一级标题可拆为日记标题，不覆盖已有记录。导入的外链图片保持占位；外来 `attachment:` 引用不得直接绑定内部资源。

单个 `.md` 导出包含标题和正文，不含心情、标签、修订或图片二进制；内部附件引用保留但不是通用图片 URL，导出前明确说明可用完整 ZIP 带走图片。完整 ZIP 重建附件及其引用，保留全部元数据；格式与去重规则由数据管理模块实现。

## 6. 撤销、AI 与权限

- 8 秒撤销窗口自服务器提交时起算；返回操作 ID、到期时间和修改后的资源版本。只能撤销本人操作，版本变化、过期或目标不可恢复时拒绝并解释，不能覆盖另一设备的后续编辑。
- 删除立即从普通读取和 AI 查询中消失，并停止涉及该来源的活动任务；正文/附件在撤销窗口内受限保留，过期清理。撤销恢复原记录，不恢复已取消任务或被清理的 AI 派生副本。
- 未吃会清空餐次食物与照片引用，用户先确认；撤销恢复完整餐次快照，仍受版本校验。
- AI 修改需要展示准确目标、修改前后、缺失信息与未知值。批准绑定资源版本和参数；过期、被修改、已取消或已消费的审批不能再次写入。
- “不提供给 AI”只控制模型使用，不增加本人查看的解锁门槛。列表仅显示锁图标，详细说明留在设置；单次授权绑定任务、资源及版本，不自动延续到下一任务。
- AI 新对话只显示轻量欢迎态；有消息后隐藏。切换到新会话不删除历史、不撤销已批准写入，也不自动取消旧云端任务。当前原型中取消模拟定时器仅是演示行为。

## 7. 可验收的交互场景

| 编号 | 操作与预期 |
| --- | --- |
| UX-01 | 手机记录午餐含米饭 150g、西兰花未知；PC 同账号 30 秒内看到同餐且未知不是 0 |
| UX-02 | PC 补西兰花 100g 后手机可见，米饭及原备注不被覆盖 |
| UX-03 | 手机与 PC 持有同一餐版本同时修改，后提交者见冲突且输入保留；不能出现静默覆盖 |
| UX-04 | 两端写日记无预览/保存按钮；光标与中文输入稳定；只在云端成功后显示已保存 |
| UX-05 | 在途保存期间继续输入，故意颠倒网络响应顺序，最终保存全部文字且不增加重复篇目 |
| UX-06 | PC 写含表格、任务列表、代码与图片的日记，手机修改普通段落再回 PC，其他块完整 |
| UX-07 | 日记日历翻年月不改记录；同日多篇可访问；空日期补记归属正确，饮食日期保持原值 |
| UX-08 | 日记自动保存修订按实际版本增加；幂等重试/无变化不新增；已移除图片仍能从合法历史修订查看 |
| UX-09 | 撤销过期或已有另一设备修改时拒绝覆盖，仍展示当前正确记录 |
| UX-10 | 未获新授权的下一 AI 任务不能从历史、摘要或 checkpoint 读取受限内容 |
| UX-11 | 图片失败可以重试，不留下假成功；取消空白日记图片不创建空篇 |
| UX-12 | 新建 AI 会话不会影响旧任务；明确停止后禁止后续写入，已完成操作如实展示 |

原型只作为交互与视觉参考。上述云端修订、跨设备冲突、图片存储、权限、任务恢复与撤销必须在真实客户端、API 和 PostgreSQL 上验收。
