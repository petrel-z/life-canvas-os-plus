## 1. 产品范围

面向多用户的个人生活管理应用，提供独立 iOS、Android 应用及电脑 Web 端，以联网使用为主，各账号数据独立。首版只实现饮食这一生活维度，核心是准确记录一日三餐；同时提供辅助日记、AI 助手和数据管理。未来维度数量不设固定限制。

界面默认中文，手机导航为“饮食、日记、AI、我的”，Web 导航为“饮食记录、日记、AI 对话、设置”。首页直接显示当天三餐。

## 3. 功能要求

### 3.1 账号与设置

- 邮箱注册、验证、密码登录、找回密码、退出登录、注销账号。
- 支持多设备登录、查看设备会话和撤销指定设备访问。
- 设置昵称、时区、深色/浅色/跟随系统主题；生日、MBTI、价值观选填。
- 退出时清理本设备的账号缓存；注销时停止任务并删除业务数据、文件、记忆及 AI 派生内容。

### 3.2 三餐记录

支持早餐、午餐、晚餐的新增、补记、编辑和删除，按日期、餐次、食物名称筛选历史记录。

| 对象 | 必须支持的信息 |
| --- | --- |
| 每餐 | 归属日期、记录时区、餐次、状态、实际进餐时间及准确程度、备注、照片 |
| 每条食物 | 名称、实际食用量、单位、数量来源；品牌、做法、生重/熟重说明选填 |
| 单位 | g、ml、个、片、杯、碗、份；保留用户原始单位 |
| 数量来源 | 明确数量、估计、未知 |

记录规则：

1. 同一账号、同一天、同一餐次只有一份记录，一餐包含多条食物明细。
2. 状态区分“未记录”“明确未吃”“已记录”。已记录至少有一条食物；删除整餐恢复为未记录；改为未吃前提示清除已有明细。
3. 已知用量必须大于零并填写单位；未知用量存为空并显示“待补充”，估计值单独标识。小数使用 Decimal/numeric 保存，通过十进制字符串传输。
4. 实际进餐时间可明确标为未知，不能用提交时间代替。补记允许选择归属日，修改个人时区不改变历史餐次归属。
5. 不自动把碗、份等换算成克数，不根据照片或模型猜测用量；首版不计算热量或营养素。

### 3.3 日记与图片

- 日记支持创建、编辑、删除、五档可选心情、逐个添加标签、日期/关键词筛选和云端修订历史查看。同一天允许多篇日记。
- 日记自动保存，不提供手动保存按钮或独立预览入口。输入停止 650ms 后提交；中文组合输入结束后再保存。仅服务器确认后显示已保存，失败保留当前草稿。
- 手机全屏编辑，标题与正文聚焦无边框，常用格式按钮位于底部；右上入口下拉设置心情、标签、日期、AI 使用限制、修订和删除。
- PC 使用三栏：左侧独立所有日记列表、中间编辑、右侧上方常驻年月日历及下方常驻日记设置。工具栏在标题下方，标准正文左边距 32px；可主动进入专注模式。
- PC 提供格式化书写与 Markdown 源码编辑，以及单篇 .md 导入导出。正文以 Markdown 为唯一持久化源，手机编辑不能静默丢失 PC 写入的复杂格式或图片。详细支持范围见交互规范。
- 日记默认不提供给 AI；本人登录后正常查看，不设置额外解锁流程。列表只显示锁图标，说明和开关留在设置内。
- 日历支持年月切换；翻月不修改选中日期，选日期打开/补记对应日记，不修改饮食日期。日记归属日期只在设置中修改，个人时区变化不移动历史记录。
- 每次实际变更的成功云端提交生成不可变修订；无变化或幂等重试不增加版本。修订首版只读查看；并发冲突返回 409，保留草稿供核对，不自动覆盖。
- 餐次和日记均支持图片上传、预览、删除；手机从相册选择，Web 从文件选择。日记图片入口位于格式工具栏，插入当前光标位置。
- 支持 JPEG、PNG、WebP，单张最大 10 MiB；手机处理 HEIC 转换、方向及压缩，并移除位置信息。文件存私有存储，访问前验证归属；上传失败可重试，历史修订引用的图片不能随正文移除立即销毁。

### 3.4 AI 助手

- 支持新建/查看/删除会话、历史消息、流式回复、执行状态、停止任务和切后台后恢复。仅新对话显示轻量图标、引导和示例，已有消息时隐藏；新建或切换会话不自动取消旧云端任务。
- 可查询三餐/日记，创建或修改餐次及食物、标记未吃、删除餐次，以及创建/修改/删除日记。
- 所有 AI 写操作先展示具体内容，用户批准后执行；可拒绝或在同账号另一设备确认，拒绝或过期结束当前任务。重复提交、重复批准及任务重试不得产生重复业务效果。
- 日期、餐次不明确时追问；用量和实际时间缺失时追问或在预览中标为未知。向已有餐次追加食物时保留原明细。
- 支持用户确认保存的偏好/目标记忆，并提供查看、修改、删除入口；默认不从私密日记提取记忆。
- 私密日记仅在用户明确选择后用于当前任务；相关回复、摘要继承 AI 使用限制，下一任务需重新授权，不能经历史或 checkpoint 自动复用。
- 餐次保存/未吃/删除、日记删除及 AI 修改提供 8 秒服务端撤销窗口，版本已变化或过期时拒绝覆盖，详见交互规范。
- 任务及确认状态持久化；等待确认时释放 Worker。断开客户端不取消任务，停止操作阻止后续写入，已完成操作明确展示。
- 单任务最多 8 轮模型调用、12 次工具调用、5 分钟执行时间；确认有效期 15 分钟，等待确认不占执行时限。单账号默认每日 50 次新任务，超额拒绝受理，额度由服务端配置。

### 3.5 数据导入导出

- 支持当前账号数据导出：三餐、食物明细、日记及修订、图片、资料偏好、记忆和可读对话历史。
- 格式为版本化 ZIP，包含 manifest、JSON 数据及附件；校验格式版本、数量、文件 hash 和关联关系。仅接受本项目支持的格式。
- Web 提供导入与导出入口；手机支持发起导出、查看任务状态和下载结果。导入前展示预检报告，用户确认后执行。
- 使用稳定来源标识去重；同包重复导入、新导出包导回原账号均不得复制已有记录。内容冲突保留目标数据并报告；整餐冲突时不混入源食物明细。
- 导入以当前账号为 owner，正确重建明细和附件关联；历史对话只读归档，不恢复工具或审批。密码、会话令牌、密钥、任务队列和 checkpoint 不导出。
- 显示进度及成功/部分成功/失败结果；导出文件 24 小时后清理。账号级导入导出与服务器灾备分开处理。

## 4. 架构与数据要求

- 使用单仓库：apps/mobile、apps/web、packages/api-client、packages/client-core、packages/design-tokens、services/backend、infra、doc。
- 后端采用模块化单体，模块为 identity、profiles、nutrition、journals、agent、data_portability；API 与 Worker 共用业务服务，分别部署。
- 调用方向为路由 → 业务服务 → 数据访问。Agent 工具调用相同业务服务，由 LangChain/LangGraph 管理执行流程。
- 核心数据包括用户/会话、餐次/食物明细、日记/修订/附件、AI 会话/消息/任务/审批/记忆、导入导出任务、操作审计；所有用户资源必须有归属。
- FastAPI 验证身份及资源归属，PostgreSQL RLS 补充隔离；服务端注入 user_id，客户端及模型不能指定身份。模型密钥仅保存在服务端。
- 餐次和明细原子保存；修改携带 version，冲突返回 409，保留未保存内容。创建、确认和导入使用幂等键；任务重复投递不能重复写入。
- 每个 AI 任务使用独立 checkpoint，恢复前验证归属；同一会话最多一个未结束任务。事件带递增序号供重连追赶；终态 checkpoint 与流事件保留 7 天，过期后返回持久化任务结果，长期消息独立保存。
- 自有 API 遵循 RESTful，使用 /api/v1、资源名和正确的 GET/POST/PUT/PATCH/DELETE 语义；完整替换使用 PUT，局部修改才使用 PATCH。Pydantic/OpenAPI 生成 TypeScript 客户端。
- 普通 JSON 成功/失败响应统一为 `{ "code": 200, "msg": "success", "data": {}, "traceId": "xxxx" }`；code 是与 HTTP 状态一致的整数，创建为 201、异步受理为 202，失败使用真实 4xx/5xx。msg 成功为 success，无数据时 data 为 {}。
- traceId 贯穿本次请求的响应头与日志，幂等重放使用当前请求的追踪标识；SSE、下载及按 HTTP 规则无响应体的情形采用对应协议，详见核心契约。
- 创建/更新时间使用 UTC，餐次另存归属日期和 IANA 时区。日志脱敏；删除源数据时清理关联 AI 派生内容及 checkpoint。

## 5. 体验与交付要求

- 云端数据为准；进入页面、回到前台、恢复联网时刷新，正常网络下其他活跃设备 30 秒内可见修改。
- 断网时保留当前编辑内容并提示未保存；不显示伪成功，不承诺退出或重启后的离线恢复。刷新不得覆盖正在编辑的草稿；日记自动保存按篇串行，保留在途请求后的新输入。
- 同区域、50 并发活跃用户测试下，普通非上传/AI API 的 p95 ≤ 500 ms；Agent 受理 1 秒内返回任务 ID，模型响应耗时单独统计。
- 提供 Web 部署产物及可安装的 iOS、Android 测试构建，验证真机登录回跳、图片、流式接收和后台恢复。
- 开发、测试、生产环境隔离；CI 执行类型检查、lint 和对应测试。PostgreSQL 集成测试覆盖用户隔离，Playwright 覆盖 Web，Maestro 与真机验证覆盖手机。
- 建立数据库与文件备份并完成恢复演练：RPO ≤ 24 小时、RTO ≤ 4 小时。API 兼容当前及上一个已发布移动版本。

## 6. 首版不包含

本地 PIN/锁屏、固定八维/评分体系、饮食基准与偏离、营养计算、食物图像识别、洞察、时间轴、旧系统数据迁移或同步、完整离线编辑同步、独立桌面安装包、社交社区、付费订阅、用户自带模型密钥。

## 7. 验收标准

1. iOS、Android、Web 可登录同一账号并共享数据；任何账号均无法访问其他账号的记录、图片、会话或任务。
2. 三餐支持多条食物与准确用量，未记录/未吃/未知份量正确区分；补记、编辑、并发冲突及小数精度通过测试。
3. Agent 不猜测缺失事实；写入需确认，跨设备确认、重复请求及 Worker 重启均不重复执行，客户端恢复后能看到最新结果。
4. 日记、图片、云端修订历史和记忆管理可用；跨端 Markdown 不丢失受支持内容，自动保存与冲突处理通过 UX-04 至 UX-08、UX-11；受限内容不会未经新授权进入下一次 AI 任务。
5. 导出后导入空账号，原始用量、单位、日期及附件关系一致；重复导入零新增，冲突和损坏包有明确报告。
6. 退出/撤销设备后访问失效；注销停止任务并清理数据及派生副本；三端关键流程、性能与备份恢复达到第 5 节要求。

## 8. 本轮收口与待落实事项

产品范围、三餐规则、手机/PC 核心交互及技术方向按本版推进。开发顺序为真实账号与三餐跨端流程，再完善日记/图片、AI、数据管理与发布验收；完整 V1 范围不因分阶段交付而缩减。

首发地区与部署区域、正式应用名称/图标、移动端签名与分发账号、生产服务预算/凭证需要在对应环境接入或发布前落实。当前可以进行本地工程和核心流程开发准备，不为未知环境编造可用凭据或上线日期。

首条真实流程的接口已设计；其余模块按开发计划细化 schema 与接口后实施。原型未完全呈现的真实上传、断网、云端冲突、权限和任务恢复状态，必须在正式页面实现并验收。完整场景清单见 [交互规范](INTERACTION_SPEC.md#7-可验收的交互场景)。
