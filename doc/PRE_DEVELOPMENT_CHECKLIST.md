## 第一条开发路径

按开发计划 T1 → T2 → T3 → T4 推进，随后分别完成 Web/手机页面并联合验收。核心业务写入先落真实 PostgreSQL，客户端共享生成接口与校验逻辑。所有“已保存”来自服务端确认；原型本地存储不进入生产协议。

## 进入下一阶段的条件

- [ ] 本地工程可运行，锁文件和迁移可复现，CI 有类型、lint、测试检查。
- [ ] 身份服务与数据库已实际连接，未验证邮箱/已撤销会话无权访问业务。
- [ ] 首条三餐流程的精度、幂等、版本冲突、用户隔离及跨设备刷新已验收。
- [ ] iOS/Android 真机与 Web 使用同一测试后端，记录构建和环境版本。
- [ ] 日记编辑器选型通过跨端 Markdown 保真、原生键盘与中文输入验证后，再实施完整日记模块。

## 开发与发布前分别落实

测试服务配置缺失时可先做本地工程及真实本地 PostgreSQL 测试，但不能把云端/真机验证标记通过。首发地区、生产部署区域与服务预算在采购/上线前落实；名称图标在发布素材制作前定稿。真实凭据通过环境配置提供，不写进文档。

正式验证结果统一放到 `doc/validation/`，每项标明环境、命令或真机步骤、实际结果和剩余问题。
